---
title: "Google Workspace SCIM provisioning"
description: "Current Google Workspace SCIM support for Uni-CLI"
---

Use [Google Workspace SAML SSO](/cloud/sso-google-workspace) when members
should authenticate to Uni-CLI with Google. Google Workspace custom SAML apps do
not currently expose a generic outbound SCIM connector that can provision users
and groups into Uni-CLI.

## Current support

Uni-CLI supports SCIM provisioning through identity providers that can send
SCIM requests to the Uni-CLI SCIM base URL with a bearer token. Google
Workspace's automated user provisioning is app-catalog based: Google provides
provisioning setup screens and app-specific guides for supported applications.

For a custom SAML app created for Uni-CLI, Google Admin provides SAML settings,
optional SAML attribute mappings, and service access controls, but does not show
the SCIM fields Uni-CLI needs:

- SCIM base URL or tenant URL
- Bearer token or secret token
- Create, update, deactivate, or reactivate user actions
- Group push or group provisioning actions
- SCIM attribute mappings such as `userName`, work email, given name, family
  name, and display name

Until Google adds Uni-CLI as a supported automated-provisioning app or exposes
generic outbound SCIM settings for custom apps, Google Workspace can be used for
Uni-CLI SSO but not for Uni-CLI SCIM lifecycle provisioning.

## What still works with Google Workspace

Google SAML SSO can authenticate Uni-CLI members and create first-login members
through Uni-CLI's just-in-time SSO provisioning. JIT provisioning is not the
same as SCIM:

- It happens when a user signs in successfully.
- It can create the Uni-CLI organization membership with the default `Member`
  role after successful SAML authentication.
- A standalone email/password signup with the same verified domain does not add
  the user to the organization or replace the SAML sign-in requirement.
- It does not continuously sync profile changes from Google.
- It does not deactivate Uni-CLI access when a Google user is suspended or
  deleted.
- It does not create SCIM-managed Uni-CLI teams from Google groups.

Use Uni-CLI member management, invitations, or another supported SCIM identity
provider for lifecycle automation.

## How to confirm in Google Admin

After setting up the Uni-CLI custom SAML app, open the Google Admin console and
check:

1. **Apps → Web and mobile apps → Uni-CLI**.
2. The app's configuration sections and side navigation.
3. Any settings named **Provisioning**, **Auto-provisioning**, **User
   provisioning**, or **SCIM**.

If those sections are not present, the app cannot consume the Uni-CLI SCIM base
URL or bearer token.

Google's general automated user provisioning page points administrators to
app-specific provisioning guides for supported apps. If Uni-CLI appears in that
supported app list in the future, follow the Google app-specific provisioning
guide and enter the Uni-CLI SCIM values from **Settings → SCIM**.

## Do not expose the SCIM token unnecessarily

Only create or rotate an Uni-CLI SCIM connector when you have an identity
provider that can use it. The bearer token is shown once and should be treated
like a password. Do not paste it into Google, tickets, screenshots, logs, or
documentation unless a provisioning screen explicitly asks for it.

## Alternatives for SCIM lifecycle automation

For automatic member lifecycle and team synchronization, use an identity provider
that supports Uni-CLI's SCIM connector:

- [Okta SCIM provisioning](/cloud/scim-okta)
- [Microsoft Entra SCIM provisioning](/cloud/scim-microsoft-entra)

Do not broaden SCIM assignment scope in the alternate provider until your chosen
SSO and SCIM lifecycle tests pass and at least one Uni-CLI owner has a working
recovery path.
